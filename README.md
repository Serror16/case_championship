# Индекс транспортной достижимости Чукотки

Этот репозиторий воспроизводит **сценарную**, а не фактическую оценку пассажирской достижимости. Для 37 населённых пунктов он считает две оценки по четырём календарным сезонам и трём ограничениям времени: 48 часов, 72 часа, 7 суток. Девять пунктов официального опорного перечня пока исключены из числителя и знаменателя из-за недостатка данных.

## Быстрый запуск

Нужен Python 3.10+; сторонние библиотеки не требуются. Из этой папки:

```bash
python src/index.py
python -m unittest discover -s tests -v
```

Расчёт создаёт `results/CORRECTED_ROSTER_37.json` с числителями, знаменателями, процентами и списками достигнутых пунктов, а также `results/CORRECTED_ROSTER_37.md` с таблицами. Код не скачивает данные во время расчёта.

## Интерактивная страница

Из корня репозитория запустите `python web/server.py` и откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Сторонние библиотеки и база данных не нужны. Сервер по умолчанию доступен только на этом компьютере.

На странице можно выбрать регион (пока Чукотка), ввести любое целое H от 1 до 168 часов, добавить соединение с интервалом «раз в N дней» или исключить существующую направленную дугу, затем пересчитать обе метрики по четырём сезонам. Для нового H исходная оценка вычисляется один раз и кэшируется на время работы сервера; опубликованные файлы в `results/` по-прежнему содержат три опорных порога. Исключение действует на все датированные отправления выбранного направления и рейса. Обратный маршрут, если включён, получает те же даты, часы и длительность. Первая и последняя даты задаются в пределах 2026 года; сезон определяется датой старта автоматически.

Название пункта в итоговой таблице открывает его подробную страницу. Там для всех 36 направлений показаны доля успешных моментов старта, достижимость хотя бы раз и самое быстрое найденное время пути по каждому сезону. Для найденной поездки можно раскрыть пример цепочки рейсов с источниками и допущениями. Направления с низкой долей успешных стартов, превышением H или отсутствием пути за 7 суток выделяются для дальнейшей проверки. Эти признаки не устанавливают единственный рейс, вызвавший низкую оценку: для рекомендаций по изменению расписания нужен отдельный анализ сценариев.

Сценарий хранится только в `sessionStorage` открытой вкладки и передаётся серверу для одного расчёта. Исходные CSV и результаты в `results/` при работе страницы не меняются. В таблице показывается результат и изменение относительно исходной сети. Пересчёт может занимать несколько секунд.

## Что именно считается

Для каждого пункта отправления и каждого другого пункта берётся самое раннее прибытие после выбранного момента старта. Проверяются старты каждые два часа, с 00:00 до 22:00 каждого дня сезона. Время ожидания и пересадки входит в предел H; при смене транспорта требуется не менее 90 минут. Все времена — UTC+12. Старты у конца 2026 года исключаются, если полный срок H выходит за пределы доступного расписания.

- **При случайном старте** — процент проверенных вариантов поездки, в которых удалось добраться за время H. Для каждого другого пункта проверяются разные дни и часы начала пути; число удачных вариантов делится на число всех проверенных.
- **Достижимо хотя бы раз** — процент других пунктов, до которых удалось добраться за время H хотя бы при одном старте за сезон. Число таких пунктов делится на 36.

Пункты назначения имеют одинаковый вес; численность населения не используется. Зима — январь–март и декабрь, весеннее межсезонье — апрель–май, лето — июнь–сентябрь, осеннее межсезонье — октябрь–ноябрь. Сезон определяется датой старта.

## Состав кода и данных

| Файл | Назначение |
|---|---|
| `src/index.py` | Полный расчёт двух оценок и запись результатов |
| `src/engine.py` | Поиск самого раннего прибытия по датированным рейсам |
| `date/transport_events_2026.csv` | Единая таблица датированных дуг: авиация, автобусы, вода и модельные подъезды |
| `date/sources.csv` | Машинный справочник источников для каждой дуги |
| `date/settlements.csv` | Опорные 46 пунктов и признак включения в расчёт 37 пунктов |
| `src/air.py` | Календарь, сезоны и часовой пояс расчёта |
| `src/bus.py` | Чтение единого датасета и сборка графа в памяти |
| `src/roster.py` | Загрузка перечня и признака включения из CSV |
| `src/scenario.py`, `src/detail.py`, `web/` | Временные изменения графа, подробности по пункту, локальный сервер и веб-страницы |
| `SOURCES.md` | Все 18 использованных первичных и контекстных ссылок с ролью каждого источника |
| `docs/index_methodology.pdf` | Подробное описание методики и три итоговые таблицы для ознакомления экспертов |
| `tests/` | Проверка правила пересадки, структуры результатов и совпадения с зафиксированным пилотом |

Входные данные расчёта находятся в `date/`; схема и значения полей описаны в `date/README.md`. Основной граф содержит 29 142 датированные направленные дуги; число больше количества физических рейсов, потому что рейс с несколькими остановками даёт несколько допустимых пар посадки и высадки. Автобусные и водные отправления, прежде записанные в Python, представлены строками общей таблицы. Ссылки на исходные расписания перечислены в `sources.csv` и `SOURCES.md`.

## Ограничения качества данных

Маршруты охватывают выбранные рейсы ЧукотАВИА, часть прибрежных рейсов, переправу через Анадырский лиман, три автобусных направления и модельные подъезды. Это **не полный граф транспорта округа**. Часы автобусов № 1, № 2 и № 100 перенесены из расписаний 2024/2025 годов. Доступность и длительность такси и поездки по ледовой дороге заданы допущениями. В некоторых местах аэропорт и населённый пункт пока представлены одним узлом без отдельного подъезда.

Расписание не гарантирует свободное место, фактический рейс, отсутствие отмены или возможность купить билет. Не учтены цена поездки и спрос. Нулевой балл означает отсутствие подходящего пути **в этой модели**, а не доказанную транспортную изоляцию. Числа следует использовать для обсуждения методики и направлений сбора данных; перед управленческим применением нужно расширить и независимо проверить сеть.

## Планы развития индекса

1. Сверить перенесённые водные и автобусные строки с первичными расписаниями и добавить дату последней проверки каждого источника.
2. Получить действующие часы всех автобусных и местных водных направлений, добавить остальных перевозчиков и девять пока неоценённых пунктов.
3. Разделить аэропорты и жилые части поселений там, где сейчас они объединены; подтвердить время и доступность каждого подъезда.
4. Проверить выборочные поездки вручную и сравнить сезонные оценки с независимым источником или фактическими перевозками.
